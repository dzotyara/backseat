# Backseat

Бот для группового чата в Telegram, который ведёт себя как участник чата, а не
как ассистент: следит за перепиской и иногда вставляет комментарий в своём
характере (см. `prompt.txt`) — саркастичный, с юмором, callback-шутками и
парой персональных пунктиков про конкретных участников. Использует любую
модель с OpenRouter (по умолчанию `thinkingmachines/inkling:free`).

## Как это работает

Бот не спрашивает модель на каждое Telegram-сообщение — это дорого и не
похоже на живое участие в разговоре. Вместо этого сообщения группируются в
батчи:

1. **Debounce.** Каждое новое сообщение перезапускает таймер тишины
   (`DEBOUNCE_SECONDS`, короче — `MENTION_DEBOUNCE_SECONDS`, если бота
   упомянули/ответили ему). Батч закрывается, когда наступает тишина.
2. **Максимальное ожидание.** Если сообщения сыплются без остановки,
   `MAX_BATCH_WAIT_SECONDS` не даёт батчу растянуться бесконечно.
3. **Лимит размера.** `MAX_BATCH_MESSAGES` форсирует обработку, если батч
   слишком разросся.
4. **Один LLM-вызов на батч.** Модель получает `CONTEXT` (более старая
   история — только для понимания разговора и callback-шуток) и `NEW`
   (собственно батч — единственное, на что можно среагировать), и сама
   решает: `respond: true/false`, а если `true` — на какое сообщение батча
   ответить (`reply_to_message_id`) и что написать (`comment`).
5. **Кулдаун.** `MIN_SECONDS_BETWEEN_COMMENTS` считается от последнего
   реально отправленного сообщения бота. Прямое упоминание/ответ боту может
   его обходить (`MENTION_BYPASSES_COOLDOWN`). Если кулдаун активен и повода
   его обойти нет — батч просто уходит в историю без вызова модели (экономия
   токенов), а не теряется.

На один батч — максимум один ответ бота. Одинаковые сообщения подряд
(например, спам одним и тем же текстом) сворачиваются в одну строку вида
`id_начала-id_конца|автор|текст|xN`, чтобы не тратить токены и не провоцировать
модель отвечать на каждое повторение отдельно.

Каждый чат обрабатывается независимо (свой буфер, свой таймер, свой лок),
и параллельные апдейты одного чата не порождают гонки: снимок текущего батча
и его очистка происходят атомарно (без `await` между ними) перед тем, как
уйти в сетевой вызов, так что новые сообщения, пришедшие во время вызова
LLM, всегда попадают в следующий батч, а не теряются и не смешиваются с
текущим.

## Промпт

Характер бота — в `prompt.txt`, а не в `.env`: удобнее редактировать и не
теряется при экранировании кавычек/переносов строк. Файл монтируется в
контейнер через `docker-compose.yml`, так что менять характер бота можно
без пересборки образа — просто отредактировать `prompt.txt` и перезапустить
контейнер (`docker compose restart`). Если файла нет — используется
`BOT_PROMPT` из `.env` как запасной вариант.

## Команды бота

- `/start` — короткое объяснение, как бот работает
- `/help` — список команд
- `/ping` — проверка, что бот жив (ответит `pong`)
- `/status` — текущие настройки (debounce, кулдаун, окно контекста,
  сколько сообщений сейчас в необработанном батче)

## Быстрый старт

1. Скопируйте `.env.example` в `.env` и заполните:
   - `TELEGRAM_BOT_TOKEN` — токен от @BotFather
   - `OPENROUTER_API_KEY` — ваш ключ OpenRouter
   - `MODEL_NAME` — модель на OpenRouter (по умолчанию
     `thinkingmachines/inkling:free`)
   - остальные параметры (debounce, кулдаун, лимиты токенов) — опциональны,
     дефолты разумны
2. При желании отредактируйте `prompt.txt` под нужный характер бота.
3. Запуск одной командой:

   ```bash
   docker compose up -d --build
   ```

4. Добавьте бота в нужный групповой чат и отключите privacy mode
   у @BotFather (`/setprivacy` → Disable), иначе бот не будет видеть
   сообщения других участников, а не только адресованные ему.

## Тесты

Покрыты ключевые сценарии батчинга: дедупликация повторяющихся сообщений,
кулдаун (и его обход упоминанием), fallback невалидного `reply_to_message_id`,
`respond=false`. Не претендует на полное покрытие гонок/debounce-таймингов —
это быстрые unit-тесты на `process_batch` и сериализацию с замоканным LLM и
Telegram API.

```bash
pip install -r requirements-dev.txt
pytest tests/ -v
```

## Файлы

- `bot.py` — aiogram-хендлеры сообщений и команд; per-chat буферизация,
  debounce/batching, кулдаун, сериализация CONTEXT/NEW, защита от гонок
- `llm_client.py` — клиент к OpenRouter (`/chat/completions`); просит модель
  вернуть `{"respond": bool, "reply_to_message_id": int|null, "comment": str|null}`,
  ограничивает параллельные запросы, даёт грубую оценку токенов для обрезки
  контекста
- `prompt.txt` — характер и стиль бота (персона), монтируется в контейнер
- `docker-compose.yml` / `Dockerfile` — запуск одной командой

## Важно про OpenRouter

Формат запроса/ответа — стандартный OpenAI-совместимый
`/v1/chat/completions`. Если модель, которую вы укажете в `MODEL_NAME`, не
подчиняется инструкции отвечать строго JSON — бот просто промолчит на этот
батч (логируется warning), потому что безопаснее пропустить комментарий,
чем отправить в чат сырой мусор.
